## 개요

WebMCP 백엔드(`webmcp/backend/app.py`)가 DB에 저장하는 정보를 확인하는 대시보드입니다.

- **`tenants`** : 멀티테넌트(도메인별 Gemini 키/한도) 설정
- **`request_logs`** : 요청 로깅 (비정상 접속 감지/분석)

### DB 구조 (webmcp)

`webmcp` DB에는 **2개 테이블**만 존재합니다.

**`tenants`** — 테넌트(도메인별) 설정

| 컬럼 | 타입 | 용도 |
|------|------|------|
| `id` | int | 테넌트 ID |
| `origin` | varchar | 도메인 |
| `site_ns` | varchar | 사이트 네임스페이스 |
| `gemini_key` | text | Gemini API 키 |
| `model_name` | varchar | 사용 모델 |
| `rate_limit` | int | 분당 호출 한도 |
| `tier` | varchar | 등급 |
| `enabled` | tinyint | 활성/비활성 |
| `created_at` / `updated_at` | timestamp | 생성/수정 시각 |

**`request_logs`** — 요청 로그

| 컬럼 | 타입 | 용도 |
|------|------|------|
| `id` | bigint | 로그 ID |
| `ts` | datetime | 요청 시각 |
| `origin` / `referer` / `user_agent` / `sec_ch_ua` | text/varchar | 요청 출처·헤더 |
| `ip` | varchar | IP |
| `path` | varchar | 요청 경로 |
| `body_len` | int | 요청 본문 크기 |
| `verdict` | varchar | 정상/차단 판정 |
| `reason` | varchar | 차단 사유 |

> 📌 **벡터(임베딩) 데이터는 저장하지 않습니다.** 이 DB는 **테넌트 설정**과 **요청 로그**만 저장합니다. 임베딩 벡터는 별도 벡터 DB(예: Pinecone, Chroma 등)에 저장하거나, 이 프로젝트에서는 사용하지 않습니다.
>
> 따라서 임베딩 모델을 변경(`text-embedding-004` → `gemini-embedding-2`)해도 **벡터 차원 불일치나 재임베딩 문제는 발생하지 않습니다.**

## 디렉토리 구조

```
webmcp/dashboard/
├── app.py              # Streamlit 대시보드 메인
├── db.py               # DB 접속 및 쿼리 헬퍼
├── requirements.txt    # Python 의존성
├── run.sh              # 실행 스크립트
├── .env.example        # DB 접속 설정 예시
└── README.md           # 이 문서
```

## 설치 및 실행

### 1. 의존성 설치

```bash
cd webmcp/dashboard
pip install -r requirements.txt
```

### 2. DB 접속 설정

`.env.example`을 복사해 `.env`를 만들고 실제 DB 접속 정보로 수정합니다.

```bash
cp .env.example .env
# .env 파일을 열어 DB_HOST / DB_USER / DB_PASSWORD / DB_NAME 수정
```

> 💡 `webmcp/backend/app.py`와 동일한 DB 접속 정보를 사용합니다.

### 3. 실행

```bash
# 방법 1: 실행 스크립트 사용 (기본 포트 8501)
./run.sh

# 방법 2: 포트 지정
./run.sh 8502

# 방법 3: 직접 실행
streamlit run app.py
```

브라우저에서 `http://localhost:8501` 접속합니다.

| 탭 | 내용 |
|----|------|
| **📈 요청 분석** | 시간대별 요청 수, verdict 분포, 도메인별/IP별 요청 수 |
| **🏢 테넌트 설정** | 테넌트(도메인별 Gemini 키/한도) 목록, 테넌트별 요청 현황, 도메인별 설정 |

## 각 기능 상세

### 📈 요청 분석
- **시간대별 요청 수**: 분 단위로 요청 추이를 꺾은선 그래프로 표시
- **요청 상태(verdict) 분포**: `ok` / 차단(`blocked_*`) 비율을 원형 차트로 표시
- **도메인(origin)별 요청 수**: 테넌트별 요청량을 막대 그래프로 표시
- **IP별 요청 수 (상위 20)**: 요청이 많은 IP를 가로 막대 그래프로 표시

### 🏢 테넌트 설정
- **전체 테넌트 목록**: 모든 테넌트를 표시하되, Gemini 키는 **마스킹**(앞 6자 + `…` + 뒤 4자) 처리
- **테넌트별 요청 현황**: 도메인별 총 요청 / 정상 / 차단 수 집계
- **도메인별 설정**: 아래 "설정 방법" 참고

### 🚫 차단 로그
- **차단된 요청 (최근 500건)**: `verdict != 'ok'`인 요청 전체 표시
- **차단 사유(reason) 분포**: 차단 사유별 막대 그래프

### 📋 전체 로그
- **전체 요청 로그 (최근 1000건)**: 최근 요청 로그 전체를 표시

## 도메인별 설정 방법 (테넌트 설정 탭)

테넌트 설정 탭에서 **도메인을 선택**하면 하나의 화면에서 아래 4가지를 모두 설정할 수 있습니다.

| 설정 항목 | 설명 | 기본값 |
|-----------|------|--------|
| **도메인 사용** (토글) | 🟢 활성 / 🔴 비활성. 비활성 시 해당 도메인 요청이 **403 차단**됩니다. | 활성 |
| **분당 호출 한도 (rate_limit)** | 1~10000 사이의 분당 요청 한도. 초과 시 **429 차단**됩니다. | 20 |
| **등급 (tier)** | `dev` / `prod` / `test` / `beta` 중 선택 | dev |
| **Gemini 모델 (model_name)** | 사전 정의된 모델 목록 또는 "✏️ 사용자 지정"으로 직접 입력 | gemini-2.0-flash |

**저장 방법**: 값을 변경한 뒤 **"💾 설정 저장"** 버튼을 누르면, 변경된 항목만 DB에 반영됩니다. 저장 후 **✅ 저장 완료 메시지**가 화면에 표시됩니다. (변경된 항목이 없으면 "ℹ️ 변경된 설정이 없습니다.")

> 💡 저장 후에도 목록이 갱신되도록 30초 캐시가 적용되어 있습니다. 새로고침하면 최신 상태를 확인할 수 있습니다.

## 사용 가능한 Gemini 모델별 특징

대시보드에서 선택할 수 있는 모델 목록과 특징입니다.

| 모델명 | 유형 | 특징 / 용도 |
|--------|------|-------------|
| **`gemini-3.1-flash-lite`** | 채팅/생성 (Flash-Lite) | 저비용·저지연 경량 모델. 간단한 질의응답, 빠른 응답이 필요한 챗봇에 적합 |
| **`gemini-3.5-flash-lite`** | 채팅/생성 (Flash-Lite) | 최신 Flash-Lite 계열. 더 나은 품질과 속도 균형. **현재 기본 추천 모델** |
| **`gemini-2.0-flash`** | 채팅/생성 (Flash) | 범용 멀티모달. 이미지·텍스트 이해, 도구 호출 지원 |
| **`gemini-2.5-flash`** | 채팅/생성 (Flash) | 2.5 계열. 추론 능력이 강화된 범용 모델 |
| **`gemini-embedding-2`** | 임베딩 (최신) | **최신 Gemini Embedding 2**. 이미지·문서(PDF) 포함, 3072차원(압축 가능), 8192 토큰. **현재 생생병원 사용 모델** |
| **`gemini-embedding-001`** | 임베딩 | Gemini Embedding 1. 텍스트 전용, 3072차원, 8192 토큰. 검색·RAG·유사도 계산 |
| **`text-embedding-004`** | 임베딩 (구형) | 구형 Gecko 기반, 768차원 고정, 2048 토큰. **2026-01 중순 지원 중단(Shutdown)** — 마이그레이션 권장 |

> 💡 **선택 가이드**
> - **챗봇/질의응답**: `gemini-3.5-flash-lite` (속도·비용 최적)
> - **고품질 답변 필요**: `gemini-2.5-flash`
> - **벡터 검색/RAG (텍스트)**: `gemini-embedding-001`
> - **이미지/문서(PDF) 포함 임베딩**: `gemini-embedding-2`
> - ⚠️ **`text-embedding-004`는 지원 중단**되어 사용하지 않는 것을 권장합니다.
> - 목록에 없는 모델을 쓰려면 **"✏️ 사용자 지정"** 을 선택해 직접 입력하세요.

### ⚠️ 임베딩 모델 마이그레이션 주의사항

`text-embedding-004`(768차원) → `gemini-embedding-2`(3072차원)로 변경 시, **벡터 DB를 사용하는 일반적인 경우** 아래 사항을 확인해야 합니다.

1. **벡터 차원(Dimension) 불일치**: 기존 벡터 DB 컬럼이 768차원으로 고정되어 있다면, 최신 모델(3072차원) 결과 저장 시 차원 불일치 에러가 발생합니다. 컬럼 크기를 3072로 확장해야 합니다.
2. **전체 데이터 재임베딩(Re-indexing) 필요**: 서로 다른 임베딩 모델이 만든 벡터는 호환되지 않습니다. 기존 벡터를 지우고 최신 모델로 처음부터 다시 추출·저장해야 정상적인 검색(RAG)이 동작합니다.

> ✅ **이 프로젝트(webmcp)에는 해당 없습니다.** 위 "DB 구조"에서 확인했듯이 `webmcp` DB는 벡터를 저장하지 않습니다. 따라서 모델명을 `gemini-embedding-2`로 변경한 것만으로 충분하며, 차원 조정이나 재임베딩은 필요하지 않습니다.
